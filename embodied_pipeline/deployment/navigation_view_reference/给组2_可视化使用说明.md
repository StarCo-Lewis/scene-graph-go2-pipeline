# 给组2 · 导航可视化（live_view）代码与运行方式

> 2026-10-30 整理。用途：你们插着狗网线时，也能看到「地图 + 规划路径 + 狗的位置/朝向 + 走过的轨迹」。
> 结论先说：**画图的程序在我们这边（`nav/tools/`），不在狗上；狗上只要导航节点在跑就够了。**
> 它只订阅、不发任何指令，不影响导航，也不动狗。

---

## 一、这套可视化是什么

狗上的导航节点在跑的过程中，会额外发三条 **JSON 小消息**（`std_msgs/String`）：

| 话题 | 频率 | 内容 |
|---|---|---|
| `/nav/feedback` | 10 Hz | 当前位姿 `cur_x/cur_y/cur_yaw`、阶段 `stage`、剩余距离/角度 |
| `/nav/planned_path` | 每次任务一次 | 规划路径 `waypoints: [[x, y, yaw], ...]`（场景系） |
| `/nav/result` | 每次结束一次 | `success / reason / elapsed / final_x / final_y / final_yaw / ...` |

`live_view.py` 就是订阅这三条，用本地的地图文件在本地画图。

★ 为什么不用「传图片」：WSL↔狗 这条通道传几万字节的图会丢，而一条 feedback 只有 80 字节。
所以是**发小消息、本地渲染**。

---

## 二、代码在哪

都在我们的 `nav/tools/` 下。你们拿到项目目录后路径是 `nav/tools/…`；狗上部署后是 `~/nav_ws/nav/tools/…`。

| 文件 | 作用 | 规模 |
|---|---|---|
| `nav/tools/live_view.py` | ★ 实时可视化主程序：订阅三条话题 → 画 2D 俯视图 → 周期存 PNG + 落盘 npz | ~250 行 |
| `nav/tools/start_live_view.sh` | 启动包装（**只适用我们的 WSL**：路径写死成 `/mnt/d/…`，会先杀残留再用 setsid 脱离会话）。你们直接跑上面那条 `python3` 就行，不用它 | ~26 行 |
| `nav/tools/replay_view.py` | 离线复看：读 live_view 存下的 npz，不连狗、不需要 ROS | ~160 行 |
| `nav/tools/619_map_v1_clean_5cm.npz` | 619 场景栅格（5 cm/格）。`live_view --grid` 指它 | 数据文件 |

地图 npz 里的字段（想自己画地图时用）：

```
occ          (H, W) uint8    1=障碍 0=自由（未膨胀）
origin       (2,)  float     栅格左下角在场景系的坐标
res          float           米/格（=0.05）
scene_origin (2,) float      场景系原点在图坐标里的位置（我们这里是 (0,0)）
```

世界坐标 ↔ 格子：`x = origin[0] + col*res`，`y = origin[1] + row*res`；`row=0` 在**下**边（`imshow(origin='lower')`）。

## 三、依赖

```
ROS2 + rclpy（我们这边是 Foxy；Humble 理论上一样，未在你们机器上验证）
numpy
matplotlib（有显示器就用 TkAgg，没有就 Agg 只落盘；不想装 matplotlib 就用第五节的方式 B）
```

还需要**在 DDS 层看得见狗**：同网段 `192.168.123.x`、同一 `ROS_DOMAIN_ID`、同一 RMW。
我们这边统一由 `env.sh` 设置（CycloneDDS + domain 0 + 绑到 192.168.123.x 那张网卡）。

★ 如果你们机器上没有 ROS2：**不建议为了看这个专门装**。没有 rclpy 就连话题都收不到（方式 B 也一样），
那种情况下要么用我们笔记本看，要么加交换机让我们这边跑（见第七节第 2 条）。

## 四、方式 A：直接跑我们的程序（有 ROS2 的机器）

```bash
# 先让 DDS 看得见狗（我们用的是这个；网卡名按你们实际改）
source ~/capo_live/env.sh

# 实时可视化（Ctrl+C 退出，退出时会补存最后一张图和数据）
python3 nav/tools/live_view.py \
  --grid nav/tools/619_map_v1_clean_5cm.npz \
  --npz  nav/tools/run_$(date +%Y%m%d_%H%M).npz \
  --out  nav/tools/live_view.png
```

关键参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--grid` | `demo_scene.npz` | 场景栅格，619 用上面那个 npz |
| `--npz` | `tools/live_view.npz` | 轨迹/路径/result 落盘，**跑完还能复看** |
| `--out` | `tools/live_view.png` | 实时快照，每 `--save-every` 秒覆盖一次 |
| `--save-every` | 5.0 | 无显示器时靠它出图 |
| `--seconds` | 极大 | 跑多久自动退出 |

无显示器也没关系：它每 5 秒存一张 `--out` 指向的 PNG，直接打开看就行。

## 五、方式 B：接进你们自己的界面（不需要我们这套画图）

如果你们已经有自己的面板，直接订阅这三条话题、自己画即可（仍需 ROS2/rclpy，只是不需要 matplotlib 和我们的画图代码）。最小代码：

```python
import json
import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, HistoryPolicy
from std_msgs.msg import String

QR = QoSProfile(depth=100, reliability=ReliabilityPolicy.RELIABLE,
                history=HistoryPolicy.KEEP_LAST)

class View(Node):
    def __init__(self):
        super().__init__('g2_view')
        self.create_subscription(String, '/nav/feedback', self.on_fb, QR)
        self.create_subscription(String, '/nav/planned_path', self.on_path, QR)
        self.create_subscription(String, '/nav/result', self.on_res, QR)

    def on_fb(self, m):
        d = json.loads(m.data)
        # stage: str, remaining_dist/cur_x/cur_y/cur_yaw: float
        print(d['stage'], d['cur_x'], d['cur_y'], d['cur_yaw'])

    def on_path(self, m):
        wps = json.loads(m.data)['waypoints']      # [[x, y, yaw], ...]

    def on_res(self, m):
        d = json.loads(m.data)
        # success, final_x, final_y, final_yaw, reason, elapsed, uncertainty, ...
        print(d['success'], d['reason'], d['elapsed'])

rclpy.init()
rclpy.spin(View())
```

★ QoS 要和发布端一致：**RELIABLE + depth 100 + KEEP_LAST**。用 BEST_EFFORT 会收不到。

## 六、输出里有什么

跑完（或每 5 秒）会存：

- **PNG**：栅格 + 规划路径（红虚线）+ 已走轨迹（蓝实线）+ 当前位置（绿点 + 朝向箭头）+ 标题里的 stage / 剩余距离
- **NPZ**：`traj`(N,3)、`traj_t`(N,)、`path_0..N`、`n_path`、`n_result`、`stage_names` / `stage_t` / `stage_remain`
  → 用 `python3 nav/tools/replay_view.py xxx.npz --grid nav/tools/619_map_v1_clean_5cm.npz` 离线复看

## 七、三个必须知道的限制

1. **坐标系还没和你们对齐（我们的已知问题 #31）。**
   `cur_x/cur_y/cur_yaw` 和 `waypoints` 都在我们的**619 场景系**：星星 = (0,0)，x 朝前、y 朝左、yaw0 = +x。
   你们的可视化原点/0 方向如果和这个不一致，叠在一起会整体差一个平移/旋转。
   **在对齐之前，别用叠图判断绝对误差**，只能看形状和相对运动。

2. **网线只有一根。** 谁的电脑插着狗网线，谁的 DDS 才能收到这三条话题。
   两台同时看需要小交换机（两台同段不同 IP）——这条**我们没验证过**，要试就现场试。

3. **它只是观察者。** 只订阅三个话题，不发布、不发运动指令、不影响任务；
   关掉它不会影响狗上导航；拔了网线它收不到新数据（画面停在最后一帧），不是故障。
