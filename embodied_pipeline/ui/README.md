这是 Python/Tk 桌面窗口，界面中文，直接读取此前生成的 D3-619 场景图。打开窗口不调用模型、不访问 WSL、不连接狗、不发送导航。

## 一、打开窗口

在 Windows 双击工程根目录的 `启动D3619现场窗口.cmd`，或在工程根目录运行：

```powershell
python -m embodied_pipeline field-console
```

启动器优先使用这台电脑已有的 Python；其他电脑可以用环境变量 `FIELD_UI_PYTHON` 指定解释器，或直接运行上述命令。图形界面只依赖 Python 标准库 Tkinter，不依赖 ROS2、浏览器或 GPU。

当前窗口默认读取 `outputs/real_scene_runs/d3_619_graph_20261022_094742_334872/scene`。源码包没有私有场景数据时，需自行提供，并用 `--scene 路径` 指定。地图投影显示所有物体，不代表障碍物栅格、可达空间或真实机器人定位。

## 二、现场输入任务、生成计划

1. 可选：浏览列表或地图中的物体，不作为指令约束。
2. 输入英文导航任务，或点击“用所选物体填写示例”。界面中文，仍保持英文输入要求；不自动翻译，不生成参考动作替换模型答案。
3. 点击“准备任务 / 生成命令”。此时仅写入任务 JSON，不调用 LLM。
4. 选择下面两种规划方式之一，不要对同一个任务同时使用两种方式。

**方式 A：规划后端一次启动，后续都在窗口中提交。**

在 WSL 的规划环境中交互设置密钥（不要把密钥发到聊天或填进代码）：

```bash
read -r -s -p 'DashScope API key: ' DASHSCOPE_API_KEY
printf '\n'
export DASHSCOPE_API_KEY
```

进入窗口的“连接 / 规划环境 / 反馈”页，核对规划 Python、embedding Python、模型路径，点击“复制规划后端启动命令”，粘贴到上述 WSL 终端执行。等待窗口显示后端在线。

在“连接 / 规划环境 / 反馈”页点击“备用：提交已准备任务给手动启动的 WSL 后端”，确认 API 费用提示。后端会串行处理，窗口自动观察本次 `planning_summary.json` 和 `engineering_plan.json`。

**方式 B：不启动常驻后端。** 点击“复制 WSL 规划命令”，在已设置密钥的 WSL 终端手动执行；窗口同样会观察结果。

两种方式都只生成计划，不会执行导航。新任务由指令决定目标，列表选择不参与校验；保留单导航动作、场景目标存在、对象绑定一致性及符号目标检查。旧固定目标 smoke 测试仍保持原协议。抓取、放置、多目标导航不能直接执行。

## 三、目前的 TCP 和反馈边界

- 本工程新增协议为 `nebula.navigation.tcp.v1`，默认地址 `192.168.123.18:8888`。需要部署配套狗端网桥；不兼容未知的原有 8888 报文，不会猜测协议。发送需握手、目标映射和逐项人工确认。
- TCP 检查需人工点击并确认，仅建立连接后关闭，不发送应用数据。成功不代表 CAPO、ROS2 Action 或导航服务已就绪。
- 不启动、重启或停止狗上节点；不把 SOP 的示例目标当作连通性检查。
- 可选择本工程导航客户端产生的 `events.jsonl`。窗口只绘制 `event=feedback` 中的 `data.current_pose`，并要求显式确认反馈 `frame_id` 对应当前场景坐标。
- 不通过改变 frame 名称实现坐标变换。如果反馈是里程计坐标、地图坐标未与 D3-619 对齐，应先取得标定变换，不应勾选确认。
- 轨迹来自日志，不是模拟运动。旧记录会显示“历史回放/反馈已过期”；没有位姿就不绘制机器人，不在起点与终点之间补动画。
- 图中的物体中心不是机器人停靠目标；真正执行前仍需确认实际起点、零朝向、桌旁安全停靠点、速度、容差和急停。

配套网桥不启动导航节点或调整运动参数。不能因为端口可连就启用运动。详见完整使用手册；离线测试使用替身驱动，不向狗发请求。

## 四、文件与恢复

- 每次新任务写入 `outputs/real_scene_runs/field_ui_<时间>_<编号>/task.json`。
- 模型结果在其 `planning/` 子目录；常驻后端原始日志在 `worker.console.log`。
- 队列、结果和心跳位于 `outputs/field_console_queue/`，不包含 API key。
- 同一任务禁止重复提交；规划目录已存在时后端拒绝覆盖，不自动补跑。
- worker 通过 `worker.lock` 防止重复启动。异常断电可能遗留锁：先确认旧 worker 和规划子进程已退出，再人工处理锁，不要在仍运行时删除。
- `.claimed.json` 保留处理证据；异常中断的任务不会自动再调用模型。请检查状态后新建任务，避免不知情重复计费。
- 关闭窗口只关闭观察界面，不终止 WSL 中已启动的规划，也不等于停止机器人。现场急停请使用遥控器/物理急停。
